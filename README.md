# CreatorFlow AI

> AI 驱动的新媒体内容创作工作流助手

CreatorFlow AI 是一个面向小红书等新媒体内容创作者的 **AI 产品 Demo**。它不是单点文案生成器，而是尝试把选题研究、内容生成、封面创意、知识沉淀和人工审核组织成一条可理解、可配置的创作工作流。

**项目阶段：Demo Preview｜作品集方向：AI 产品经理**

## 一句话产品定位

将分散的 AI 创作工具整合为一套以创作者决策为中心的内容生产工作台，帮助用户减少重复操作，同时保留对选题、表达和最终内容的控制权。

## 产品背景

内容创作者需要反复完成选题、标题、正文、封面设计和内容复盘等工作。现有流程通常散落在搜索工具、聊天机器人、图片工具和个人文档中，导致：

- **流程碎片化**：选题、写作和视觉设计需要在多个工具之间切换。
- **重复劳动多**：每次创作都要重新整理背景、要求、提示词和素材。
- **个人风格难沉淀**：历史内容与创作偏好没有形成可复用的知识资产。
- **AI 输出缺少控制**：单次生成很难体现完整上下文，也容易跳过创作者的判断。
- **工具状态不透明**：用户难以确认当前使用的模型、数据来源和输出是否为真实结果。

AI 的价值不只是生成一段文案，而是将这些重复环节串联为完整工作流，并在关键节点让创作者选择、审核和确认。

## 产品目标

帮助小红书等内容创作者提高内容生产效率，减少工具切换和重复输入成本，并验证以下 AI 产品假设：

1. 工作流式体验是否比单点生成更适合复杂内容创作。
2. 候选方案加人工选择是否能提升用户对 AI 输出的控制感。
3. 模型配置、数据来源与 Mock 状态透明化是否能增强产品可信度。
4. 创作知识沉淀是否能为后续个性化生成和 RAG 提供基础。

## 目标用户与典型场景

### 目标用户

- 需要稳定更新内容的个人创作者。
- 同时负责选题、写作和视觉方向的小型内容团队。
- 希望使用 AI 提效，但不愿把内容判断完全交给自动化工具的用户。

### 典型场景

创作者输入本次内容任务和表达要求，从候选选题中选择方向，生成标题与正文，再进入 Visual Studio 形成封面创意；确认后的素材和经验可以进入知识库框架，为后续创作提供参考。

## 产品方案

CreatorFlow AI 将创作过程拆分为可观察的阶段：

```text
创作简报
   ↓
选题研究与候选方向
   ↓  人工选择
标题 / 正文 / 封面提示词
   ↓  人工审核
Visual Studio 封面创意
   ↓
草稿保存与知识沉淀
```

核心原则是 **Human-in-the-loop**：AI 负责准备候选内容，创作者在关键节点做选择与审核。当前 Demo 不执行自动发布。

## 核心功能

| 模块 | 当前能力 | 当前状态 |
| --- | --- | --- |
| AI 内容生成 Workflow | 展示内容任务在不同创作环节中的输入、状态与输出 | Demo / 模拟运行 |
| Content Creator | 提供候选选题，并生成标题、正文和封面提示词 | 支持 Mock Provider |
| Model Hub | 管理文本与图片模型配置，展示 Provider、模型与连接状态 | 配置框架 |
| Visual Studio | 将主题转化为封面创意方向，生成最多四个图片候选 | 支持 Mock 图片 |
| Knowledge Repository | 提供知识条目管理、搜索和生成引用框架 | 本地演示存储 |
| Research Beta | 提供研究搜索、人工勾选和确认入库流程 | 默认 Demo / Mock 回退 |
| Safety Guard | 对生成内容进行基础检查，并展示风险信息 | Demo 能力 |

## 关键产品决策

### 1. 从“一键生成”改为“候选 + 选择”

内容创作具有主观性。产品优先让 AI 提供方向和候选，由用户决定下一步，而不是直接替用户完成并发布内容。

### 2. 明确区分 Mock 与真实能力

页面会标记 Demo / Mock 状态，避免把演示数据、模拟图片或模型输出包装为真实平台结果。

### 3. 模型配置贴近使用场景

文本模型与图片模型分别服务于内容创作和视觉创意，同时保留 Model Hub 作为统一配置入口，让模型状态对用户可见。

### 4. 先建立知识框架，再扩展 RAG

当前版本先验证知识条目的管理、检索与引用路径，生产级数据库、向量检索和完整 RAG 留在后续阶段。

## 产品架构

面向非技术读者，可以把系统理解为四层：

| 层级 | 作用 | 对用户的价值 |
| --- | --- | --- |
| 产品界面 | Next.js 前端承载创作、模型、视觉和知识库页面 | 在一个工作台完成主要创作步骤 |
| 业务接口 | API Routes 接收生成、研究和知识库请求 | 将界面操作连接到后端能力 |
| AI 能力层 | Model Provider 抽象层统一文本与图片模型接口 | 可以在 Mock 与后续真实模型之间切换 |
| 内容记忆层 | Knowledge Repository 管理和检索创作知识 | 为个性化内容与后续 RAG 提供基础 |

```text
用户
  ↓
CreatorFlow 工作台（Next.js）
  ↓
业务接口（API Routes）
  ├── AI 能力层（Model Provider）
  └── 内容记忆层（Knowledge Repository）

部署目标：Vercel
```

## Demo 展示说明

### 本地启动

```bash
npm install
npm run dev
```

启动后访问 `http://localhost:3000`。默认 Demo / Mock 模式不需要配置真实 AI 密钥。

### 建议体验路径

1. 在首页了解工作台和当前 Demo 状态。
2. 进入 **Content Brief** 创建内容任务简报。
3. 在 **Content Creator** 选择选题并体验标题、正文和封面提示词生成。
4. 前往 **Visual Studio** 查看图片创意候选与模型状态。
5. 在 **Content Intelligence Library** 了解研究结果人工确认和知识沉淀流程。
6. 在 **Agent Workflow** 查看多阶段工作流的模拟执行。
7. 在 **Model Hub** 查看文本与图片 Provider 的配置框架。

> Demo 中出现的 Mock 研究数据、文案和图片仅用于展示产品流程，不代表真实小红书数据或真实模型效果。

## 当前版本限制

- 当前为 **Demo Preview**，重点验证产品流程、信息架构和交互方案。
- 默认使用 **Mock AI Provider**，不代表生产环境中的真实模型输出。
- 未接入真实小红书数据，不提供真实趋势、爆款抓取或平台分析。
- 未接入生产级数据库，Knowledge Repository 当前为本地演示实现。
- 未实现自动发布小红书。
- 未实现完整商业化、账号、权限、计费和运营系统。
- Workflow 页面为流程模拟，不代表 Agent 已能自主执行全部创作任务。

## Roadmap

### Phase 1：产品 Demo

完成核心页面、内容创作流程、模型配置、Visual Studio 和知识库框架的 Demo 展示。

### Phase 2：真实大模型接入

在安全的服务端配置基础上接入真实文本与图片模型，完善模型切换、错误处理、输出评估和成本控制。

### Phase 3：数据库和 RAG

接入生产级数据库，完善知识资产管理、向量检索、引用追踪和个性化内容生成。

### Phase 4：Agent 自动化工作流

探索由 Agent 协调选题、生成、审核、视觉创意与复盘环节的自动化工作流，并保留关键节点的人工确认。
